# Отчёт по работе «АХ: Агент-художник»

## Выполнили

* Екатерина — MAS, генерация (Yandex ART + SD), VLM-контур, техчасть отчёта
* Мадина — упаковка, сайт, публикация, часть отчёта

## Мотивирующий абзац (Project Statement)

Наша работа — эксперимент на стыке генеративного искусства и агентных
систем. Мы не просто генерируем картинки: три LLM-агента (Сновидец,
Толкователь, Арт-директор) ведут последовательный диалог, превращая
абстрактную тему «сон» в конкретный художественный промпт. Затем два
независимых генератора (Yandex ART и Stable Diffusion 1.5) создают
конкурирующие версии, а VLM-критик оценивает результат по четырём
критериям и предлагает улучшения.

Главная находка — **VLM-критика не всегда улучшает результат**: в 3 из 5
случаев вторая версия получила оценку ниже первой. Мы не стали это скрывать,
а сделали центральной точкой исследования: контур обратной связи — это
инструмент, а не волшебная кнопка. Сайт-галерея собирает все 15 изображений,
диалоги агентов, критику и график оценок в одну живую историю — со
сравнением V1, V2 и Stable Diffusion для каждого сна.

## Использование ИИ

### MAS и генерация (Екатерина)

Многоагентная система построена на трёх LLM-агентах (YandexGPT через
Responses API): **Сновидец** придумывает сюрреалистичный образ,
**Толкователь** находит слабые места и предлагает усиления,
**Арт-директор** собирает финальный промпт для генерации.

Изображения создаются двумя движками:
* **Yandex ART** (модель `aliceai-image-art-3.0`) — основная версия
* **Stable Diffusion 1.5** через `diffusers` на GPU — для сравнения

Каждый сон проходит цикл: V1 → критика VLM → уточнение промпта → V2.
Итог: 5 снов × 3 версии = 15 изображений.

### VLM-контур обратной связи (Мадина)

Использована VLM-модель Qwen 3.6 через Yandex Cloud. VLM получает
картину и исходный художественный промпт, оценивает по четырём
критериям (соответствие концепции, сюрреалистичность, композиция,
атмосфера) и возвращает развёрнутую критику. Арт-директор переписывает
промпт с учётом замечаний, генерируется V2, VLM оценивает повторно.

Цикл ограничен одной итерацией — это защищает от зацикливания и
избыточных расходов API. Все оценки сохранены в `data/painting_*.json`
и сведены в `vlm_scores.csv`.

### Coding-агент для сайта (Мадина)

Сайт-галерея сгенерирован через **SourceCraft** (coding-агент).
Начальный промпт и итерации зафиксированы в `docs/AGENTS.md` и
`docs/prompts.md`. Сайт опубликован на GitHub Pages и читает данные
из `data/painting_*.json` — то есть является «живой» витриной
результатов MAS, а не статичной картинкой.

## Результаты

### Картины и диалоги (Екатерина)

Полные тексты диалогов агентов сохранены для каждого сна в
`data/painting_01.json` … `painting_05.json`. Для каждой картины
доступны V1 (Yandex ART), V2 (после VLM) и SD-версия.

### VLM-обратная связь (Мадина)

Сводка оценок VLM:

| № | Картина | До VLM | После VLM | Изменение |
|---|---------|--------|-----------|-----------|
| 1 | Библиотека забытых воспоминаний | 6,5 | 7,0 | +0,5 |
| 2 | Время, которого не существует | 7,25 | 7,0 | −0,25 |
| 3 | Одиночество среди миллионов голосов | 5,75 | 9,5 | +3,75 |
| 4 | Ошибка в реальности | 8,25 | 6,75 | −1,5 |
| 5 | Может ли машина мечтать? | 9,0 | 8,5 | −0,5 |

**Средний балл:** 7,35 → 7,75 (+0,40).
**Улучшились:** 2 из 5. **Ухудшились:** 3 из 5.

Это важный вывод: VLM-критика **не гарантирует** улучшения. В некоторых
случаях вторая версия теряла атмосферу или детали, которые были в
первой. Контур обратной связи — инструмент, а не волшебная кнопка.

### Сайт (Мадина)

Сайт-галерея: **https://ekaterina3002.github.io/Agent_Artist_Dreams/**

Реализовано:
* 5 снов с переключением V1 / V2 / SD
* Раскрывающиеся диалоги агентов (Сновидец → Толкователь → Арт-директор)
* Критика VLM для обеих версий
* График оценок «До / После»
* Адаптивная вёрстка (мобильные / десктоп)
* Модальное окно для просмотра картины в полном размере

## Выводы

В ходе работы мы:
* Построили многоагентную систему, где три LLM-агента последовательно
  превращают абстрактную тему в конкретный промпт для генерации.
* Сравнили два движка генерации — Yandex ART и Stable Diffusion 1.5 —
  и убедились, что у каждого своя эстетика.
* Замкнули контур обратной связи через VLM: картина → критика →
  уточнение промпта → повторная генерация.
* Сгенерировали сайт-галерею через coding-агента и опубликовали
  на GitHub Pages.

**Ключевые уроки:**

1. **VLM-критика — не гарантия улучшения.** В 3 из 5 случаев вторая
   версия получила оценку ниже первой. Модель субъективна, а
   «улучшение» по одному критерию может ухудшить другой.

2. **Формат данных важнее реализации.** Фиксация JSON-схемы
   (`painting_*.json`) в начале работы позволила сайту, VLM и MAS
   работать с одними данными без переделок.

3. **Coding-агент хорошо генерирует каркас, но требует правок.** Сайт
   получился «из коробки», но потребовалась ручная правка путей
   (`data/`, `images/`), чтобы всё заработало на GitHub Pages.

4. **Разделение на слои экономит время.** Мы работали параллельно:
   один — генерация и диалоги, второй — VLM и упаковка. Без созвонов,
   через PR и фиксированные интерфейсы.

Работа научила нас не только технической стороне (API, VLM, генерация,
Pages), но и организации совместной работы над общим репозиторием.
